- CAP04-002 is merged into `main`; run the cluster lifecycle script `verify`, `namespace` and `status` on the dedicated `k3d-twn-capstone04` cluster.

## Steps

### 1. Update repository and validate shell syntax

```bash
git status --short
git switch main
git pull --ff-only origin main
git fetch origin
git switch --track origin/feat/cap04-003-online-boutique-deployment
bash -n scripts/capstone04-deploy.sh
```

Before switching branches, preserve any uncommitted changes. If a local feature branch already exists, `git switch feat/cap04-003-online-boutique-deployment` and `git pull --ff-only` instead.

### 2. Inspect cluster capacity and current workloads

```bash
kubectl --context k3d-twn-capstone04 get nodes
kubectl --context k3d-twn-capstone04 top nodes
kubectl --context k3d-twn-capstone04 -n online-boutique get all
docker system df
```

These commands do not mutate cluster state.

### 3. Validate the versioned manifest without creating workloads

```bash
bash scripts/capstone04-deploy.sh fetch
bash scripts/capstone04-deploy.sh plan
```

The script retrieves a pinned file from the public source repository, verifies expected markers, and performs a **server-side dry run** against the explicitly named lab context and namespace.

### 4. Deploy only after preflight and scope review

```bash
bash scripts/capstone04-deploy.sh deploy
```

The script repeats server-side validation and then requests an explicit interactive confirmation before applying resources. Unlike the status/plan commands, this is a real workload change.

### 5. Validate Deployment readiness and frontend

```bash
kubectl --context k3d-twn-capstone04 -n online-boutique get deploy,pods,svc
kubectl --context k3d-twn-capstone04 -n online-boutique rollout status deployment/frontend --timeout=180s
kubectl --context k3d-twn-capstone04 -n online-boutique port-forward service/frontend 8080:80
```

The port-forward command occupies its own terminal. In a **second Terminal** visit `http://localhost:8080`. Confirm product browsing, add to cart and simulated checkout. If other Deployments fail to become ready, inspect events and logs before concluding the application is healthy.

## Safety and recovery

- All writes use explicit `--context k3d-twn-capstone04` and `--namespace online-boutique`.
- Existing AWS EKS contexts and banking clusters are never deployment targets.
- This script does **not** provision a cloud cluster, prune Docker data or delete resources.
- Initial online-shop traffic uses local port-forward. A manifest may include `LoadBalancer` Service semantics, but we do not require public exposure.
- Do not claim Redis persistence. The upstream demo's Redis uses ephemeral `emptyDir`.
- Cleanup/undeploy is intentionally not automated yet; define a safe, namespace-scoped process once deployment behavior is verified.
- Image compatibility on Apple Silicon and actual memory adequacy must be validated on the user's environment, not inferred from static manifests.
