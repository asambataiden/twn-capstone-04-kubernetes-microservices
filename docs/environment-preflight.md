## Decision gate 2 — Local development tools

Run on your **Mac** in Terminal. Commands are intentionally read-only. A missing tool should print `not installed` rather than stopping the script.

```bash

sw_vers
uname -m

echo "== CPU and RAM =="
sysctl -n hw.ncpu
sysctl -n hw.memsize

echo "== Installed tools =="
for tool in git docker kubectl kind helm aws terraform; do
  if command -v "$tool" >/dev/null 2>&1; then
    printf '%s: %s\n' "$tool" "$(command -v "$tool")"
  else
    printf '%s: not installed\n' "$tool"
  fi
done

echo "== Version commands (where available) =="
command -v docker >/dev/null 2>&1 && docker --version || true
command -v kubectl >/dev/null 2>&1 && kubectl version --client || true
command -v kind >/dev/null 2>&1 && kind version || true
command -v helm >/dev/null 2>&1 && helm version --short || true
```

### Safe cluster-creation procedure (operator-run, not executed)

The following intentionally names a new cluster, requires confirmation of the Docker engine, refuses an existing cluster name, and uses an explicit kubeconfig context for verification.

```bash
set -euo pipefail
CLUSTER_NAME=twn-capstone04
docker info >/dev/null
if k3d cluster list -o json | grep -q '"name": *"twn-capstone04"'; then
  echo "Cluster name already exists; refusing to modify it" >&2
  exit 1
fi
k3d cluster create "$CLUSTER_NAME" --servers 1 --agents 0 --wait
kubectl --context "k3d-$CLUSTER_NAME" cluster-info
kubectl --context "k3d-$CLUSTER_NAME" get nodes -o wide
```

**Safety rule:** Always include `--context k3d-twn-capstone04` in subsequent `kubectl` commands until the current-context state has been deliberately verified. The `k3d cluster create` operation may change the current kubeconfig context, so verify again after creating the cluster. Creating this cluster does not affect or delete other clusters; it consumes local Docker resources.

**Open:** Official TWN assignment, disk headroom and full Online Boutique memory capacity must be checked before applying application manifests. Source images may have architecture compatibility constraints on arm64; verify image manifests before deployment.

## Repeatable automation (CAP04-002)

The repository now includes [`scripts/capstone04-cluster.sh`](../scripts/capstone04-cluster.sh), a Bash-only operator script with explicit subcommands and strict error handling **inside the subprocess**, rather than modifying the interactive Zsh session.

```bash
bash scripts/capstone04-cluster.sh preflight
bash scripts/capstone04-cluster.sh verify
bash scripts/capstone04-cluster.sh namespace
bash scripts/capstone04-cluster.sh status
```

For a fresh rebuild, `bash scripts/capstone04-cluster.sh create` is idempotent with respect to an already existing named cluster. When starting a new environment, confirm you intend to create `twn-capstone04`. The script never deploys the application.

The `destroy` subcommand requires an exact interactive confirmation and deletes only the dedicated cluster by its name. It is **not** part of ordinary deployment or validation and should only be run after evidence has been saved.

## First automation execution — diagnosis and corrective action

The operator confirmed:
- `bash -n scripts/capstone04-cluster.sh` completed successfully.
- `preflight` discovered `twn-capstone04` as running, without touching the existing stopped banking clusters.
- `verify` confirmed the dedicated k3d node **Ready**, and all active `kube-system` Pods, including Traefik, were Ready/Running.
- `namespace` created `online-boutique`, then the post-create check reported an **incorrect missing-context error**.
- `status` also reported a missing context, despite `preflight` and `verify` earlier identifying the same context.

**Root cause:** `require_context` piped `kubectl config get-contexts -o name` to `grep -Fxq`. `grep -q` can close the pipe as soon as it finds a match, causing the upstream process to exit with SIGPIPE; `pipefail` then fails the condition even when the requested context exists.

**Fix:** Capture the context list into a variable first, then pass it to `grep -Fxq` through a here-string (not a live pipe). This preserves strict error checking while preventing the false-negative pipeline race.

**Recovery:** Do **not** recreate or delete the cluster or namespace. Fetch the updated feature branch and rerun `bash -n`, `verify`, `namespace`, and `status`. The `namespace` operation is idempotent and should report that the existing namespace is reused.

The fix is committed in this PR; execution of the corrected version on the operator's Mac remains to be verified.
