- **UPSTREAM:** Verified constraints documented by the existing Online Boutique source repository. These are not TWN assessment rules.
- **BOOTCAMP-ALIGNED (PROPOSED):** Intended learning outcomes suggested by the project topic and earlier TWN Kubernetes lessons. Exact official assignment still requires confirmation.
- **EXTENSION (OPTIONAL):** Independent engineering enhancements to consider after a working baseline.

## Nonfunctional design criteria

- **Security:** No secrets in Git, scoped Kubernetes permissions, minimal frontend exposure, avoid privileged containers.
- **Maintainability:** Reuse upstream artifacts, keep environmental differences in overlays/values, avoid duplicate manifest trees.
- **Reproducibility:** Record exact image versions, Kubernetes runtime/version, manifests and verification commands.
- **Reliability:** Health probes and resource bounds must be understood and validated before tuning.
- **Cost control:** Local cluster first unless explicit assessment requirement requires paid managed infrastructure; document teardown.

## Decision log (open)

| Decision | Default | Why / review condition |
|---|---|---|
| Cluster | local `kind` | Upstream supports `kind`; re-evaluate if official TWN assignment requires Linode LKE or other platform |

| Frontend access | `kubectl port-forward` locally | No cloud load balancer needed for first validation |
| Helm/service mesh/Terraform | deferred | Existing examples are not themselves a requirement |

## Acceptance gate before implementation

1. Read and record the **exact official TWN Project 04** description and submission constraints.
2. Confirm target cluster type (local vs managed), access, CPU/RAM availability and required demonstration format.
3. Decide whether original upstream image versions are acceptable and pullable in the chosen environment.
